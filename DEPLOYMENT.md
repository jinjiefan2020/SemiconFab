# SemiconFab.org — Production Deployment Guide (v1.0.0 Static Architecture)

This document describes the standard deployment procedure for **SemiconFab.org** on Cloudflare Pages.

---

## Architecture: Purely Static

As of release 1.0.0, SemiconFab is architected as a **purely static application**:

- **Zero Serverless Functions**: No Cloudflare Workers or Pages Functions runtime.
- **Zero Database Overhead**: No Cloudflare D1 edge database; all legacy database bindings and edge scripts decommissioned.
- **Single Source of Truth**: All data assets (`catalog.json`, `schema.json`, `benchmark/routes.json`, `twin/events-t1-fifo.jsonl`) are delivered directly from Cloudflare Pages global edge CDN with immutable caching and sub-millisecond TTFB.

---

## 1. Standard Deployment Method: Cloudflare Pages Git Integration (Connect to Git)

The primary and standard production deployment pipeline is automated via Cloudflare Pages GitHub integration:

- **Git Provider**: GitHub (`jinjiefan2020/SemiconFab`)
- **Production Branch**: `main`
- **Build Preset**: `None`
- **Build Command**: `(none / empty)`
- **Build Output Directory**: `.`

Every push to `main` (or tag release) automatically triggers an atomic production build and global edge deployment across Cloudflare's network within seconds.

---

## 2. Blue-Green Deployment & Zero-Downtime Rollout

For major releases or infrastructure migrations, a blue-green deployment strategy ensures zero downtime:

1. **Deploy New Project (Green)**:
   - Create a clean Pages project connected to the repository (`Connect to Git`), tracking branch `main`.
   - Verify all routes and assets on the assigned `*.pages.dev` preview domain.
2. **Smoke Verification on Green**:
   - Spot-check key endpoints: `/`, `/twin`, `/benchmark`, `/catalog-demo.html`, `/add-equipment`, `/data-standard`, `/verification`.
   - Confirm zero console errors, correct provenance rendering, and 200 HTTP responses.
3. **Switch Custom Domain**:
   - In Cloudflare Pages Dashboard, navigate to Custom Domains on the Green project.
   - Attach `semiconfab.org` (and `www.semiconfab.org`). Cloudflare updates DNS routing instantaneously with zero downtime.
4. **Retain Blue as Rollback**:
   - Keep the previous project (Blue) in standby for 30 days as an instant rollback target if unforeseen regressions arise.

---

## 3. Manual CLI Deployment (Alternative)

For emergency deployments or direct testing, deployments can also be executed via Wrangler CLI:

```bash
# 1. Install dependencies
npm install

# 2. Verify formatting and linting
npm run format:check
npm run lint

# 3. Deploy directory to Cloudflare Pages
npx wrangler pages deploy . --project-name=semiconfab
```

---

## 4. Custom Domain & Global Edge Network

The production site is bound to the apex domain `semiconfab.org`:

- Custom Domain: `https://semiconfab.org`
- Pages Dev Preview: `https://semiconfab.pages.dev`

SSL/TLS certificates and global CDN edge routing are managed automatically by Cloudflare.

---

## 5. Equipment Submission Flow

Equipment contributions and taxonomy extensions do not use server-side submission endpoints:

1. **Contributor Web Interface**: Users author equipment specifications through `/add-equipment` (`add-equipment.html`), which validates against `schema.json` entirely in-browser.
2. **Submission Protocol**:
   - Primary: **Download JSON** / **GitHub Issue / PR** generated by the client-side prefill link.
   - Secondary: Direct email export to `info@semiconfab.org`.
3. **Maintainer Ingestion**: Maintainers validate incoming contributions using the schema validator in `tools/validator` (`PYTHONPATH=tools/validator python3 -m schemavalidator validate <record.json>`) and merge validated records into `catalog.json` via GitHub pull requests. Detailed runbook instructions are in `SUBMISSION.md`.
